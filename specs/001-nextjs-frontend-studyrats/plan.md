# Implementation Plan: Next.js SSR Frontend for StudyRats

**Branch**: `001-nextjs-frontend-studyrats` | **Date**: 2026-05-24 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/001-nextjs-frontend-studyrats/spec.md`

---

## Summary

Build a Next.js 14+ App Router SSR-first frontend for the StudyRats study group platform. The frontend consumes the existing Spring Boot HATEOAS backend (confirmed running at port 9090) via a BFF (Backend for Frontend) pattern: auth flows proxy through Next.js API routes that set httpOnly cookies, while data-fetching pages render server-side using those cookies. Both backend prerequisites (CORS configuration and the `GET /checkin/user/{idUser}` endpoint) are **already implemented** — no backend changes are required.

---

## Technical Context

**Language/Version**: TypeScript 5 / Node.js 18+ (Next.js 14 minimum requirement)

**Primary Dependencies**:
- `next@14+` — App Router, Server Components, API Routes
- `react@18+` / `react-dom@18+`
- `axios` — HTTP client with interceptors for HATEOAS + auth
- `js-cookie` — client-side cookie reading for `studyrats_token_pub`
- `react-hook-form` — form state management + validation
- `tailwindcss` — utility-class styling
- `jest` + `@testing-library/react` + `@testing-library/jest-dom` — unit tests
- `playwright` — E2E tests (auth, check-in, ranking critical flows)

**Storage**: httpOnly cookies (session state only); no persistent client-side storage

**Testing**: Jest (unit, 100% coverage required) + Playwright (E2E for critical flows)

**Target Platform**: Web browser (desktop-first, mobile-functional); Docker container for deployment

**Project Type**: SSR web application (frontend only; backend is a separate Spring Boot service)

**Performance Goals**:
- LCP ≤ 2.5s (Core Web Vitals "Good" threshold — constitution requirement)
- INP ≤ 200ms
- CLS ≤ 0.1

**Constraints**:
- Port 3000 (dev server); must not conflict with backend port 9090
- `next.config.ts` must have `output: 'standalone'` for Docker
- `NEXT_PUBLIC_*` vars baked at build time; runtime env vars for server-side URLs

**Scale/Scope**: Single-user study platform; small team (1–10 users per group); no pagination required for initial release

## Implementation Phases (Summary)

Phase 1 design artifacts are complete. Implementation proceeds via `/speckit-tasks`.

### Recommended task order

1. **Project bootstrap** — `create-next-app`, install deps, configure `.env.local`, `next.config.ts`, `tsconfig.json`, `jest.config.ts`, `playwright.config.ts`, `.gitignore`
2. **Type definitions** — `types/index.ts` (no logic; tested by TypeScript compiler)
3. **HATEOAS utility** — `lib/api/hateoas.ts` (pure functions; 100% unit-testable)
4. **Session utility** — `lib/auth/session.ts` (server-only; tested via mock cookies)
5. **API client** — `lib/api/client.ts` (Axios; dual-URL; interceptors)
6. **API services** — `lib/api/auth.ts`, `lib/api/groups.ts`, `lib/api/checkin.ts` (unit tests with Axios mocks)
7. **AuthContext** — `contexts/AuthContext.tsx` (unit test: logout calls fetch, updates state, redirects)
8. **Middleware** — `middleware.ts` (unit test: protected paths redirect when cookie absent)
9. **BFF routes** — `app/api/auth/login`, `logout`, `register` (unit tests with mocked `lib/api/auth`)
10. **Root layout** — `app/layout.tsx` (hydrates AuthContextProvider server-side)
11. **Protected layout** — `app/(protected)/layout.tsx` (redirects when session null)
12. **Auth pages + forms** — login page + LoginForm, register page + RegisterForm (E2E: auth flow)
13. **Dashboard** — `app/(protected)/dashboard/page.tsx` + `GroupCard` (SSR; tested with mock session + mock groups)
14. **Check-in** — `app/(protected)/checkin/page.tsx` + `CheckinForm` (E2E: check-in flow)
15. **History** — `app/(protected)/checkins/page.tsx` + `CheckinCard` (SSR; graceful degradation test)
16. **Groups** — create page + `GroupCreateForm`, join page + `GroupJoinForm`
17. **Ranking** — `app/(protected)/groups/[idGroup]/ranking/page.tsx` + `RankingTable` (E2E: ranking flow; parallel fetch test)
18. **Dockerfile** — multi-stage build; `next.config.ts` standalone; test Docker build
19. **docker-compose.yml** — add frontend service with dual-URL env vars
20. **CI/Lighthouse** — `npm audit`, lint, unit tests 100%, E2E, Lighthouse Web Vitals gate
